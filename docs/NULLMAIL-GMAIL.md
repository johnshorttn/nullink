# Gmail integration — 12 October 2026

The application now implements Gmail connection, import, polling sync, cached reading and explicit sending. **No live Google account has been connected or tested.** Production is blocked on owner configuration below. Local VPS mail remains first and its SMTP path is unchanged.

## Exact owner setup

1. In a Google Cloud project enable Gmail API, configure the OAuth consent audience and authorized/test users for John's intended account, and create a **Web application** OAuth client. Consent must grant `openid`, `email`, `https://www.googleapis.com/auth/gmail.readonly`, and `https://www.googleapis.com/auth/gmail.send`. Google may require restricted-scope verification/security review according to the chosen audience/use; do not claim consent is configured merely because the code exists.
2. Register exactly `https://nullmail.nullverse.cloud/api/v1/gmail/callback`. If connecting through the alternate host, separately register `https://nullmail.216.158.238.236.sslip.io/api/v1/gmail/callback` if Google accepts that host; otherwise use the primary host. Callback is an authenticated existing Nullink session route, not a new login/audience.
3. Install `/etc/nullmail/google-oauth.json`, root-owned, group `nullmail`, mode 0640, containing `client_id`, `client_secret`, `redirect_uris` (array of exact registered URLs), and `egress_ready` (initially false). Use the web-client values, not a service-account key. This file is currently absent. Never add it to Git or browser JavaScript.
4. Generate one Fernet key with the service's Python `cryptography` library directly into `/etc/nullmail/google-token.key`, root-owned, group `nullmail`, mode 0640. Do not print it. Keep a restricted independent key backup: replacing/loss of this key requires account reauthorization. This file is currently absent. `/usr/bin/python3` has the encryption dependency installed and was checked.
5. The current unit has `IPAddressDeny=any`, `IPAddressAllow=localhost`, and `RestrictAddressFamilies=AF_UNIX AF_INET`. **No network controls were changed.** An administrator must supply an approved loopback HTTPS CONNECT proxy (or equivalently reviewed policy) with exact HTTPS destinations `oauth2.googleapis.com:443`, `openidconnect.googleapis.com:443`, and `gmail.googleapis.com:443`, normal certificate/hostname verification, and no open forwarding. Configure `HTTPS_PROXY=http://127.0.0.1:<approved-port>` in a scoped Nullmail service drop-in only after that proxy is approved/provisioned. Do not use an unrestricted proxy, arbitrary IP exceptions for Google ranges, disable certificate verification, or remove the deny policy. No such proxy is supplied/assumed by this release. Browser consent additionally needs browser access to `accounts.google.com`. Set `egress_ready:true` only after the approved path works; it is an administrator assertion, not a network diagnostic.
6. Restart only Nullmail after installing the reviewed configuration. Sign in as the existing owner, open Setup → External Gmail → Connect Gmail with Google, consent, then explicitly choose **Import Gmail history**. A connection alone does not import mail. Each worker tick imports one bounded page per account; browser visibility does not stop sync. No outbound message is required for connection/import verification.

Until these steps are complete, Setup and `/api/v1/gmail/status` list the actual missing files/network readiness and do not offer an operational Connect button. No Google credentials or consent status can be inferred from the missing configuration.

## Shipped behavior

- Existing authenticated session plus exact-origin CSRF for connect/import/manual-sync. One-use, expiring hashed OAuth state bound to actor/session; S256 PKCE; exact registered redirect; code exchange only server-side. Tokens encrypted with Fernet in `workspace.sqlite3`; restrictive filesystem permissions. No Google passwords, scraping, browser-held Google tokens, arbitrary endpoint URLs, or provider redirects.
- Stable account ID from authenticated actor and Google `sub`, verified email matched to Gmail profile. Only Google's verified primary address is a sending identity. Send-as aliases are not supported. A conflicting local From address is rejected to avoid ambiguous routing. Existing local From choices remain first and independent of inbox visibility.
- Separate Gmail cache under `/var/lib/nullmail/app/gmail-cache`; global message IDs incorporate provider/account/native Gmail ID and survive folder moves. No copied/moved local VPS messages. Cases reference `{provider:"gmail",account_id:"gmail:<32 hex>",id:"<64 hex>"}`; membership, counts, notes and history still recheck mail permissions. Cross-thread/cross-provider Cases remain distinct from labels.
- Explicit historical import: 20 IDs per list page; durable next-page checkpoint; deduplicated upserts; historic imports are marked seen in the same SQLite transaction and do not automatically execute rules. Once import completes, history polling processes new messages and observed label changes. Checkpoint advances only after the page succeeds. History expiry pauses for explicit reimport, rather than silently resyncing old mail. Backoff persists across restarts for rate limits/outages. Cached messages survive Google deletion and display a retained-copy notice when a deletion event is observed.
- Individual raw messages are limited to 2 MiB like the local reader. Oversize/no-longer-available messages are skipped with a durable reason in `gmail_skipped`; no retry loop blocks later pages. History pages with more than 100 affected messages fail boundedly rather than starting an unbounded batch. Initial import excludes Spam/Trash under Google's default list behavior. Local reader/search/attachments and reference-based threading apply to cached messages; Gmail native thread IDs are retained internally.
- **Local-only semantics:** labels, Cases, priority, read/unread flags, archive/trash/folder moves, and rule effects never modify Google. Gmail label IDs are observed metadata, not a synced label editor. Subsequent sync does not undo local folder/flag choices. Rules process new cached inbox messages even with clients closed; explicit preview/run is required for existing messages. Imported Sent mail is available through the messages API; the web Sent navigation remains the existing submission audit view.
- Explicit Gmail send uses the verified primary identity and Gmail `messages.send`, behind the existing durable request/draft claim and actor/identity audit. It never falls back to SMTP. Unknown acceptance is locked against resend; no automatic provider send retry. Accepted does not mean delivered. Tests use a fake provider only.

## Limits and remaining work

Live OAuth/consent/import/send verification is blocked on the three setup requirements (client/consent, encryption key, approved egress). Provider label/folder/read writeback, Google send-as aliases, push notifications, automatic historic rule runs, dedicated cached-Sent UI, and account deletion/revocation UI are not implemented. Polling and message parsing use the existing bounded app worker and shared mutation lock; large mailboxes may take time and provider latency can delay concurrent app writes. This is the existing single-owner app, not deployed multiuser hosting. No Android APK was built; see shared API parity documentation.

Primary Google references checked during implementation: [web-server OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect), [Gmail synchronization and expired history](https://developers.google.com/workspace/gmail/api/guides/sync), [messages.send](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/send), and [scope classifications](https://developers.google.com/workspace/gmail/api/auth/scopes).
